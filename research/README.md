# 有限状态验证机制研究

该目录是可直接运行的合成机制实验，仅使用 Python 标准库，不调用模型、不联网、不操作真实设备。

```bash
python -m unittest discover -s research -p "test_*.py" -v
```

从仓库根目录执行，Python 3.10 或以上。测试文件定义 20 项测试，其中一项遍历八种合成状态的全部 255 个非空子集。

## 实现内容

- `World` 用三个布尔变量构造八种合成状态，`function_ok` 是人为定义的合成目标。
- `Verifier.active` 根据设备、采集顺序、证据等级和后续动作影响筛选当前证据。
- `record_action` 保留可能的未执行、部分执行与执行结果，不假定动作达到理想效果。
- `belief` 返回与有效证据相容的状态；空集合被识别为冲突。
- `next_check` 比较检查对相反结果状态对的最坏情况区分能力及成本。
- `guard_counterexamples` 在有限模型内查找满足当前条件但目标仍不成立的反例。

## 不实现或不证明的内容

`fixture_verified` 是测试夹具的预设观察条件，不是视觉模型置信度，也不是对真实用户照片的可信认证。所有概率、动作影响和功能契约均不能直接推广到真实设备。

本代码没有实现完整的领域规程审核、必测优先服务策略、真实模型调用、人工接单或持久化服务工作流。`MODEL_SUPPORTED_IN_FIXTURE` 只表示合成夹具内条件满足，不代表设备已经修复。

修改模型时必须重新评估状态覆盖与观察假设，不应只增加正例或修改断言使测试通过。
